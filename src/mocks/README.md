# 화면 테스트 데이터의 출처

## A회사 — 백엔드 시드 기준

- 원천: `pulsemetry-backend/tools/dev-seed`의 `SeedScenario.kt`, `UsageSeed.kt`, `FrontendFixture.kt`와 서버 `VendorCatalog`.
- 생성물: `generated/company-a.json`, `generated/vendor-catalog.json`. 직접 수정하지 않는다.
- 사용: `company-a.ts`에서 노출하고 Storybook 단계별 fixture가 복제해 사용한다.
- 실제 API 실패 시 대체 데이터로 사용하지 않는다. 실제 E2E는 기존 DB 시드를 조회한다.

```sh
# 백엔드 시드·카탈로그를 수정했다면 해당 저장소에서 이미지 먼저 빌드
# docker compose build dev-seed
npm run fixtures:sync
npm run fixtures:sync -- --check
```

고정 기준일은 2026-10-11이며 다른 기준일은 인자로 지정한다. 이 명령은 DB를 읽거나 수정하지 않는다.
이미 적재된 DB가 최신 생성물과 같다는 뜻이 아니다. 기존 DB 초기화는 별도 결정이다.

| 항목        | A회사 기본 시나리오                                                                                                   |
| ----------- | --------------------------------------------------------------------------------------------------------------------- |
| 구성원      | owner 1, admin 1, 일반 구성원 99, 초대 상태 6(대기·만료 각 3)                                                         |
| 팀          | 플랫폼팀·제품팀·데이터팀·디자인팀·프론트엔드팀·백엔드팀·보안팀·AI팀·SRE팀·QA팀 + 미배정/팀 이동 이력                  |

| 온보딩      | 완료                                                                                                                  |

팀별 활성 구성원은 플랫폼 12·제품 12·데이터 10·디자인 8·프론트엔드 10·백엔드 12·보안 8·AI 10·SRE 10·QA 8명이다.
팀 소속 100명과 미배정 1명을 합쳐 활성 구성원 101명이며, 초대 상태 6명은 별도다.

`usage.models`는 백엔드가 최근 28일 관측에서 내보낸 모델 ID 목록이다. 2026-10-11 기준
Claude Sonnet 5.5·Fable 5.1·Haiku 5.5와 GPT-6.1 Sol·GPT-6 Astra·GPT-6 Luna를 사용한다.
180일 전체에 적용하는 화면 검증용 구성으로, 실제 모델 출시 이력을 재현하지 않는다.

가격은 합성 테스트 값이다. 97명의 관측 인원과 10석 계약을 빼서 미사용 좌석을 만들지 않는다.
`managedVendors`의 관측 지표는 서버 카탈로그의 명시 매핑으로 계산한다. Claude Code는 Claude에,
Codex는 ChatGPT/Codex에 연결하며 관측 상태는 `partial`이다. 매핑이 없는 Cursor·Copilot은
`unobserved`이고 관측 인원·시각은 null이다. 관측은 도구 사용이며 좌석 배정이나 청구 근거가 아니다.
fixture는 요청 원본 180일 전체를 담지 않는다. 전체 요청·세션·수신 수와 기간별 비용은 백엔드
`dev-seed plan <기준일>`에서 확인하고, DB 적재 검증은 `verify`로 수행한다.
기존 기간 약정은 `legacyContracts`에 분리한다. $0 약정과 미입력 구분·구 ID 호환성 회귀용이며
새 좌석 계약으로 변환하거나 합산하지 않는다.

Storybook의 수집/벤더/팀 단계는 A 기본 데이터에서 **온보딩 진행 상태를 바꾼 별도 화면 시나리오**다.
완료된 A 원본을 수정하지 않으며 각 스토리마다 복제한다. 로딩·실패·빈 목록은 별도 변형이다.
브라우저 목 테스트의 `server_only`는 프론트 하드코딩 방지용 카탈로그 확장 시나리오로 유지한다.

## 기존 Codeworks UI 데모 — A회사 데이터가 아님

`organization.ts`, `vendors.ts`, `overview.ts`, `member-seats.ts`, `activity.ts`, `vendor-usage.ts`는
API 전환 전 화면의 Codeworks 데모다. 기존 UI 테스트의 148석·117명·128대 등은 이 프로필의 값이며
A회사의 서버 요구사항이나 실제 적재 결과가 아니다. 목 계약·좌석·팀을 A회사 응답에 합치지 않는다.
설정 페이지는 서버의 등록 제품·계약·정책을 조회한다. 기존 화면 배치는 유지하며 데모 값으로 대체하지 않는다.
제품·플랜 목록은 별도로 복제하지 않고 `catalog.ts`의 생성된 서버 카탈로그를 사용한다.

## 계약과 관측의 구분

제품당 하나의 활성 등록과 기존 시작일을 유지하는 계약 정정은 사용자 결정으로 확정했다.
도구 관측과 등록 제품은 서버 카탈로그 매핑을 따른다. 계약 금액은 관측 인원과 별개이며,
합계는 유효 계약만 포함하고 만료·시작 예정·미입력 제외 건수를 함께 표시한다.
유효 계약이 없으면 0이며, 유효 계약 자체의 필요한 값이 누락되면 해당 합계는 null이다.
