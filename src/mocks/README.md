# 화면 테스트 데이터의 출처

## A회사 — 백엔드 시드 기준

- 원천: `pulsemetry-backend/tools/dev-seed/SeedScenario.kt`와 `VendorCatalog.kt`.
- 생성물: `generated/company-a.json`, `generated/vendor-catalog.json`. 직접 수정하지 않는다.
- 사용: `company-a.ts`에서 노출하고 Storybook 단계별 fixture가 복제해 사용한다.
- 실제 API 실패 시 대체 데이터로 사용하지 않는다. 실제 E2E는 기존 DB 시드를 조회한다.

```sh
# 백엔드 시드·카탈로그를 수정했다면 해당 저장소에서 이미지 먼저 빌드
# docker compose build dev-seed
npm run fixtures:sync
npm run fixtures:sync -- --check
```

고정 기준일은 2026-09-28이며 다른 기준일은 인자로 지정한다. 이 명령은 DB를 읽거나 수정하지 않는다.
이미 적재된 DB가 최신 생성물과 같다는 뜻이 아니다. 기존 DB 초기화는 별도 결정이다.

| 항목 | A회사 기본 시나리오 |
| --- | --- |
| 구성원 | owner 1, admin 1, 일반 구성원 10, 초대 상태 2 |
| 팀 | 플랫폼·제품·데이터·디자인 + 미배정/팀 이동 이력 |
| 좌석 계약 | Claude Team 표준 8석 × $20 + 프리미엄 2석 × $100 = $360/월 |
| 계약 미입력 | ChatGPT/Codex |
| 관측 | 직전 28일 8명, 252개 이벤트. 두 도구 중복 사용 포함 |
| 설치 | 10대, 정책 v1 적용 기록. 원문 미수집 |
| 온보딩 | 완료 |

가격은 합성 테스트 값이다. 8명의 관측 인원과 10석 계약을 빼서 미사용 좌석을 만들지 않는다.
`managedVendors`의 관측 지표는 null이다. 공급자 사용 기록을 계약 UUID에 귀속할 근거가 없기 때문이다.
기존 기간 약정은 `legacyContracts`에 분리한다. $0 약정과 미입력 구분·구 ID 호환성 회귀용이며
새 좌석 계약으로 변환하거나 합산하지 않는다.

Storybook의 수집/벤더/팀 단계는 A 기본 데이터에서 **온보딩 진행 상태를 바꾼 별도 화면 시나리오**다.
완료된 A 원본을 수정하지 않으며 각 스토리마다 복제한다. 로딩·실패·빈 목록은 별도 변형이다.
브라우저 목 테스트의 `server_only`는 프론트 하드코딩 방지용 카탈로그 확장 시나리오로 유지한다.

## 기존 Codeworks UI 데모 — A회사 데이터가 아님

`organization.ts`, `vendors.ts`, `overview.ts`, `member-seats.ts`, `activity.ts`, `vendor-usage.ts`는
API 전환 전 화면의 Codeworks 데모다. 기존 UI 테스트의 148석·117명·128대 등은 이 프로필의 값이며
A회사의 서버 요구사항이나 실제 적재 결과가 아니다. 목 계약·좌석·팀을 A회사 응답에 합치지 않는다.
설정 페이지는 서버의 등록 제품·계약·정책을 조회한다. 기존 화면 배치는 유지하며 데모 값으로 대체하지 않는다.
제품·플랜 목록은 별도로 복제하지 않고 `catalog.ts`의 생성된 서버 카탈로그를 사용한다.

## 미정인 제품 결정

제품당 하나의 활성 등록과 기존 시작일을 유지하는 계약 정정은 사용자 결정으로 확정했다.
공급자 관측과 조직 계약의 연결, 부분 계약 합계 표시 정책은 미정이다. 일부 계약이 미입력이면 전체 합계는 null로 유지한다.
