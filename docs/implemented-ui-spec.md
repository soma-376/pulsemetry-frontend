# Pulsemetry 현재 구현 화면 명세

이 문서는 PROJ-186·187 통합 이전 `develop`의 `51f2a7c`를 기준으로 실제 렌더링된 화면과 소스 코드를 대조해 정리한 구현 명세다. 화면이 제공하는 기능과 아직 연결되지 않은 기능을 구분하는 것이 목적이다. API 계약의 상세 요청과 응답 형식은 [화면별 API 구현 요청서](api/README.md)를 함께 참고한다.

> 과거 화면 스냅샷입니다. 현재 SSO·업무 API 통합 상태는 README와 `api/README.md`, `bff-auth.md`를 따릅니다.

## 구현 범위 요약

| 화면 | 경로 | 데이터 상태 | 현재 구현 수준 |
| --- | --- | --- | --- |
| 로그인 | `/login` | Enrollment API | 회사 OIDC 로그인, 세션 갱신과 로그아웃, 온보딩 상태에 따른 이동이 연결됨 |
| 도입 문의 | `/contact` | 로컬 폼 | 입력 검증과 확인 상태만 구현됨. 실제 접수나 메일 발송은 하지 않음 |
| 온보딩 | `/onboarding` | Enrollment와 Dashboard API | 수집 정책, 벤더 등록, 팀 생성, 완료 처리가 연결됨. 초대 발송은 비활성 상태 |
| 개요 | `/overview` | Dashboard API와 Enrollment 세션 | 사용량과 계약을 실제 API에서 조회함. 설치 명령은 현재 응답에서 제공되지 않아 `-`로 표시될 수 있음 |
| 팀 분석 | `/teams` | 프론트엔드 목 데이터와 로컬 상태 | 분석, 정렬, 상세, 팀 관리는 동작하지만 서버 저장은 하지 않음 |
| 구성원 | `/members` | 프론트엔드 목 데이터와 로컬 상태 | 검색, 필터, 정렬, 초대, 팀과 역할 편집을 로컬에서 처리함. 메일 발송과 좌석 회수는 연결되지 않음 |
| 설정 | `/settings` | Dashboard 조회와 Enrollment 관리 API | 벤더와 계약 관리, 수집 정책 저장이 연결됨. 일부 정책과 알림은 조회 전용 |
| 운영과 보안 | `/ops` | 없음 | 안내용 자리표시자만 구현됨 |

루트 `/`는 별도 화면 없이 `/overview`로 이동한다.

## 공통 화면 구조와 상태

대시보드 화면은 왼쪽 내비게이션과 상단 전역 필터, 조직 수집 현황, 본문으로 구성된다. 내비게이션은 접기와 펼치기를 지원하고 개요, 팀 분석, 운영과 보안, 구성원, 설정으로 이동한다. 하단에는 조직, 사용자, 관리자 배지와 로그아웃이 표시된다.

전역 필터는 조회 기간, 비교 기준, KST 표시, 새로고침, 5분 자동 갱신, CSV, 테마 전환을 제공한다. 비교 기준은 이전 기간, 전주, 없음 중에서 선택한다. 기간 선택기는 직접 날짜 범위를 고르거나 오늘, 이번 주, 이번 달, 최근 1년을 적용할 수 있다. 현재 CSV 버튼은 비활성 상태다.

공통 조회 UI는 최초 로딩, 기존 데이터를 유지한 재조회, 오류와 재시도, 빈 상태를 구분한다. 수집 현황도 로딩, 수집 이력 없음, 상태 확인 불가, 오류와 재시도를 별도로 표시한다. 조회 중에는 중복 새로고침을 막고, 저장 성공은 토스트로 알린다.

## 로그인과 도입 문의

### 로그인

로그인은 회사 이메일 하나를 입력받는다. Enrollment의 회사 탐색 API에서 복수 소속이면 회사를 선택하고, 브라우저가 state·PKCE를 생성한 뒤 실제 IdP 로그인으로 이동한다. 이메일 탐색은 인증이 아니다. `/auth/callback`은 state 검증 후 일회용 코드를 교환하고 `/me`의 회사·관리자 권한을 확인한다. 온보딩 완료 조직은 `/overview`, 미완료 조직은 `/onboarding`으로 이동한다. 실패·취소·미등록 회원은 우리 화면에서 안내하며 임시 정보와 URL 코드를 정리한다. 세부 계약은 [OIDC 안내](oidc-login.md)를 따른다.

다음 상태가 화면에 구현되어 있다.

- 잘못된 이메일 형식과 등록되지 않은 조직
- 로그인 진행 상태와 다른 이메일로 재시도
- 사용자 취소, 연결 오류, 권한 부족, 네트워크 오류
- 조직 관리자 문의와 도입 문의 이동
- 정상, 사용자 취소, 연결 오류, 권한 부족, 조회 실패를 선택하는 개발용 데모 시나리오

세션 요청은 401을 받으면 한 번 토큰 갱신을 시도한다. 로그아웃은 Enrollment API를 호출한 뒤 로컬 세션과 조직 상태를 비우고 `/login`으로 이동한다.

### 도입 문의

회사명과 회사 이메일을 검증하고 입력 확인 상태를 보여 준다. 현재 화면은 실제 문의를 전송하지 않으며, 이 제한을 확인 메시지와 하단 안내에 명시한다.

## 온보딩

온보딩은 세 단계 흐름이며 앞 단계의 저장 결과를 유지한다. 로그인하지 않았거나 설정 조회에 실패하면 로그인 또는 재조회 동작을 제공한다.

### 수집 정책

프롬프트와 응답 원문을 저장할지 선택한다. 수집하지 않음은 사용량과 토큰 수만 집계하고, 수집함은 코드나 개인정보가 포함될 수 있음을 안내한다. 선택 전에는 다음 버튼이 비활성화되며, 저장 후 벤더 단계로 이동한다.

### 벤더와 플랜 등록

제품, 선택 플랜, 계약 종료일, 표시 이름을 입력한다. 제품 카탈로그는 Claude, ChatGPT와 Codex, Cursor, GitHub Copilot, Gemini Code Assist와 기타 직접 입력을 지원한다. 계약 정보는 선택 사항이며 벤더 하나 이상을 등록해야 다음 단계로 이동할 수 있다.

등록한 수동 벤더는 목록에서 삭제할 수 있다. 카탈로그나 플랜 조회, 등록, 삭제 오류는 입력을 보존한 채 재시도할 수 있다.

### 팀과 초대

현재 팀 목록을 보여 주고 팀 생성과 삭제를 지원한다. 팀 이름은 최대 40자이며 한글, 영문, 숫자, 공백과 `- _ . ( ) & /` 문자를 허용한다. 구성원 초대 UI는 이메일, 팀, 역할 필드를 갖지만 현재 연동 준비 중으로 비활성화되어 있다. 사용자는 이 단계를 건너뛰거나 완료할 수 있다.

## 개요

개요는 선택 기간의 조직 사용량과 현재 계약 정보를 서로 독립적으로 조회한다. 한쪽 조회가 실패해도 다른 쪽의 성공한 데이터는 유지한다.

데이터가 있으면 다음 내용을 표시한다.

- KPI: 사용 관측 인원, 토큰 비용, 월 좌석 계약액, 세션, 보안 경보와 알림
- 일별 사용 환산액 추이와 키보드 또는 포인터 탐색
- 모델별 환산가치 구성과 모델 선택
- 벤더별 계약 좌석, 사용 관측 인원, 회수 후보, 월 좌석 계약액과 상세 드로어
- 상위 팀과 미배정 사용량 요약, 팀 분석 화면 이동

비교 데이터가 충분할 때만 증감률을 표시한다. 누락 값은 0으로 만들지 않고 `-` 또는 미관측으로 구분한다. 부분 관측이면 관측 일수를 알리고, 선택 기간에 데이터가 없으면 다른 기간을 선택하도록 안내한다.

조직에서 신호를 한 번도 받지 않은 경우 KPI 대신 데몬 설치, 계약 정보 입력, 팀 매핑의 세 단계 안내를 표시한다. 첫 신호를 기다리는 상태와 계약 설정 이동을 제공한다.

## 팀 분석

팀 분석은 선택 기간과 비교 기준을 공통 필터에서 받는다. 관측 데이터가 없으면 값을 0으로 표시하지 않고 설치 안내로 이동한다.

데이터가 있으면 다음 기능을 제공한다.

- 비용, 토큰, 세션 축 전환
- 팀별 누적 추이와 팀 표시 체크박스
- 팀명, 합계, 사용자당, 세션당, 비교 증감 정렬
- 팀 행을 선택해 모델별 환산가치와 팀 상세 드로어 확인
- 모델별 토큰 대비 비용 산점도
- 팀별 벤더 사용 비중
- 팀별 사용자 수, 세션, 토큰, 환산 금액, 캐시 적중 집계
- 사용자별 정렬, 팀 전환, 페이지 단위 더보기
- 팀 생성과 수정

현재 분석 값과 팀 관리 변경은 프론트엔드 목 데이터와 로컬 조직 상태를 사용한다. 서버 API에는 아직 연결되지 않았다.

## 구성원

구성원 화면은 전체 구성원, 좌석 회수 후보, 초대 대기, 팀 미배정 수를 요약한다. 본문은 초대 대기, 좌석 회수 후보, 팀 미배정 사용자, 구성원 목록으로 구성된다.

구성원 목록은 이메일과 팀 검색, 사용자와 팀과 사용 환산액과 최근 관측 정렬, 상태 필터, 20명 단위 더보기를 지원한다. 행을 선택하면 상세 드로어에서 상태, 팀, 역할, 벤더 좌석을 확인하고 팀과 역할을 편집할 수 있다.

초대 모달은 여러 이메일 입력, 공통 또는 개별 팀과 역할 지정, 중복과 형식 검증을 제공한다. 재발송, 초대 취소, 초대의 팀과 역할 수정도 화면에서 동작한다. 다만 모두 로컬 상태 변경이며 실제 메일은 발송하지 않는다.

팀 미배정 사용자는 여러 명을 선택해 한 번에 팀을 지정할 수 있다. 좌석 회수 후보는 벤더와 좌석 유형, 마지막 활동을 보여 주지만 확인 모달에서 외부 벤더 관리가 연결되지 않았음을 알리고 실제 회수는 수행하지 않는다. 전체 명단 CSV도 현재 실제 파일을 만들지 않는다.

## 설정

설정은 로그인 세션의 조직을 기준으로 현재 상태를 조회한다. 전체 설정, 벤더 카탈로그, 벤더 상세는 각각 독립된 로딩과 오류 상태를 갖는다.

### 벤더 연동

좌석 지출, 종량 지출, 활성 좌석, 미설정 벤더를 요약하고 등록 벤더의 계약 상태를 표시한다. 계약 상태는 유효, 미입력, 만료, 시작 예정 등을 구분한다.

벤더 추가와 편집 드로어에서 제품, 플랜, 표시 이름, 계약 종료일, 좌석 유형, 좌석 수, 월 단가를 입력한다. 계약 저장, 계약 비우기, 수동 벤더 삭제를 지원하며 버전 충돌이 발생하면 입력을 유지한 채 최신 내용 불러오기를 명시적으로 선택하게 한다. 저장과 삭제 후 관련 조회 캐시를 갱신하고 성공 토스트를 표시한다.

### 수집 정책

현재 정책 버전과 적용 설치 수를 표시한다. 프롬프트 원문 수집 토글은 확인 모달을 거쳐 저장한다. 변경은 이후 설치 등록부터 적용되며 기존 기기는 자동 변경되지 않는다는 안내가 있다.

미적용 설치 목록은 최대 100대의 설치 ID, 팀, 적용 버전, 마지막 신호를 표시한다. 업데이트 확인 알림 보내기는 현재 비활성 상태다. 좌석 회수 기준과 집계 보존은 조회 전용이고, 마지막 수집 시각을 함께 표시한다.

### 알림 규칙

비용 급증, 한도 초과, 비허용 모델 호출, 미승인 도구 연결 규칙과 임계값을 표시한다. 현재 토글은 모두 조회 전용으로 비활성화되어 있다.

## 운영과 보안

현재는 아직 구현 전이라는 안내와 개요로 돌아가기만 제공한다. 예정 범위로 세션 조회와 보안 알림을 설명하지만 실제 조회나 조작은 없다.

## 환경 변수

프론트엔드는 루트 `.env.local`을 자동으로 읽는다.

| 변수 | 용도 | 로컬 값 |
| --- | --- | --- |
| `NEXT_PUBLIC_ENROLLMENT_API_URL` | 브라우저가 OIDC 로그인을 시작하는 공개 백엔드 주소 | `http://localhost:8080` |
| `ENROLLMENT_API_URL` | BFF에서 인증·관리 백엔드로 요청하는 주소 | `http://localhost:8080` |
| `DASHBOARD_API_URL` | BFF에서 조회 백엔드로 요청하는 주소 | `http://localhost:8081` |
| `BFF_ORIGIN` | 요청 출처 확인·세션 쿠키에 사용하는 프론트 주소 | `http://localhost:3000` |
| `BFF_SESSION_KEYS` | 세션 쿠키 암호화 키. 서버 전용 비밀값 | 별도 생성 |
| `E2E_SEED_DATE` | E2E가 기대하는 시드 기준일 | `2026-09-28` |

업무 API는 동일 출처 BFF를 거친다. 조회할 조직은 로그인 세션에서만 가져오며, 세션이 없으면 조직 데이터를 조회하지 않는다. Storybook과 브라우저 테스트는 세션 fixture로 조직을 지정한다.

백엔드 루트 `.env`는 Docker Compose가 읽으며 `PULSEMETRY_LOCAL_SEED_DATE=2026-09-28`과 `PULSEMETRY_LOCAL_SEED_SCENARIOS=A,B,C`를 설정한다. Spring 앱은 이 파일을 자동으로 읽지 않으므로 호스트 실행은 `local` 프로필을 사용해야 한다.

## 현재 제약과 후속 연결 대상

- 팀 분석과 구성원은 실제 서버 조회와 저장으로 교체해야 한다.
- 구성원 초대 메일, 벤더 좌석 회수와 복원, 설치 업데이트 알림은 외부 동작이 없다.
- CSV 버튼과 전체 명단 CSV는 실제 내보내기가 없다.
- 알림 규칙, 좌석 회수 기준, 집계 보존은 현재 수정할 수 없다.
- 운영과 보안 화면은 자리표시자다.
- 도입 문의는 검증과 확인만 수행하며 접수하지 않는다.
- 로컬 개발 서버만 실행하고 백엔드를 실행하지 않으면 개요와 설정은 정상적으로 오류와 재시도 상태를 표시한다.
